**Вопрос: что разрешает политика AdministratorAccess? Почему для повседневной работы нельзя использовать root?**


Политика `AdministratorAccess` разрешает делать всё со всеми сервисами и ресурсами AWS: создавать, менять и удалять. Root — это главный владелец аккаунта, его права нельзя ограничить. Если пароль root украдут или я сама случайно что-то сломаю, пострадает весь аккаунт. У пользователя IAM права можно ограничить, включить для него MFA и в любой момент отозвать доступ. Поэтому root нужен только для редких задач, например для настройки самого аккаунта.

- `System status check` проверяет «железо» и сеть AWS. Если она не прошла, проблема у AWS, сама я исправить её не могу (обычно помогает Stop → Start, тогда машина переедет на другой физический сервер).

**Вопрос: в каких случаях стоит включать детальный мониторинг?**


Базовый мониторинг присылает метрики раз в 5 минут, детальный — раз в минуту, но за отдельную плату. Детальный нужен, когда важно быстро заметить проблему: боевой сайт, где короткий скачок нагрузки уже опасен, настройка сигналов (alarms) и автоматическое масштабирование. Для учебного сервера хватает базового.

## Задание 4. Подключение по SSH


**Что делала и зачем.**


SSH — это защищённый удалённый вход на сервер. Для Windows (PowerShell) команда такая:


```powershell

ssh -i $HOME\.ssh\<nickname>-keypair.pem ec2-user@<Public-IP>

```


- `-i` — файл приватного ключа;

- `ec2-user` — стандартный пользователь Amazon Linux;

- `<Public-IP>` — публичный адрес сервера.


При первом входе ответила `yes`. Приглашение поменялось на `[ec2-user\@ip-172-31-xx-xx ~]$`, значит я уже внутри сервера. Проверила, что nginx работает: `systemctl status nginx`.


**📸 Скриншот 6.** Успешное подключение по SSH и вывод `systemctl status nginx`.
![Скриншот](https://raw.githubusercontent.com/Cloud-Computing-Evelina/timecapsule/main/screenshots/Снимок%20экрана%202026-10-08%20204006.png)


**Вопрос: почему для входа на EC2 используется ключ, а не пароль?**


Пароль можно подобрать, а боты постоянно перебирают пароли на всех серверах в интернете. Ключ состоит из двух частей: публичная лежит на сервере, а приватная только у меня и никуда не передаётся. Подобрать такой ключ практически невозможно, а украсть его можно только с моего компьютера.

## Задание 5. Статический сайт


**Что делала и зачем.**


Создала три страницы `index.html`, `about.html`, `contact.html` со ссылками друг на друга и скопировала их на сервер командой `scp` (выполняется на моём компьютере, не на сервере):


```powershell

scp -i $HOME\.ssh\<nickname>-keypair.pem index.html about.html contact.html ec2-user@<Public-IP>:~

```


Файлы попали в домашнюю папку ec2-user. Напрямую в папку nginx их положить нельзя: она принадлежит root, а я вхожу как ec2-user. Поэтому на сервере скопировала их через sudo:


```bash

sudo cp ~/*.html /usr/share/nginx/html/

ls -l /usr/share/nginx/html

```


Открыла `http://<Public-IP>`: сайт работает, ссылки между страницами тоже.

**Вопрос: что делает команда scp и чем она похожа на ssh?**


`scp` копирует файлы между моим компьютером и сервером. Она работает поверх SSH: тот же порт 22, тот же ключ и то же шифрование. Разница в том, что `ssh` даёт мне командную строку на сервере, а `scp` только передаёт файлы.

**Вопрос: чем Stop отличается от Terminate? За что продолжаешь платить, пока экземпляр остановлен?**


`Stop` выключает сервер, но он остаётся: диск (EBS) и данные сохраняются, экземпляр можно запустить снова (публичный IP при этом изменится). `Terminate` удаляет экземпляр навсегда, и обычно вместе с ним удаляется корневой диск. Пока сервер остановлен, за вычисления (процессор и память) я не плачу, но плачу за диск EBS, который продолжает храниться.

# Часть 2. Продвинутый уровень


## Как проходит запрос


Сервер похож на ресторан:


- **nginx** — администратор у входа. Принимает запрос на порту 80 и готовые файлы (картинки, стили) отдаёт сам.

- **PHP-FPM** — кухня. nginx передаёт ей запросы, которые требуют выполнить PHP-код. Они общаются через unix-сокет `/run/php-fpm/www.sock` (это как сетевое соединение, только внутри одной машины).

- **PostgreSQL** — склад. Хранит пользователей и капсулы. Слушает только `localhost:5432`, из интернета её не видно.

## Задание 12. Обновление приложения (вариант A, вручную)


**Что делала и зачем.**


Настроила процесс ручного обновления приложения из GitHub. При выпуске новой версии сервер получает обновлённый код, устанавливает необходимые зависимости, выполняет настройку базы данных и перезапускает PHP-FPM.

Такой способ позволяет обновлять приложение без повторного создания виртуального сервера.

Весь код приходит из репозитория, а не копируется с ноутбука, поэтому всегда понятно, какая версия работает на сервере.


**Вопрос: что увидит посетитель, который откроет сайт в момент git pull? Что случится, если после git pull не выполнится composer install?**


`git pull` заменяет файлы по одному, и это занимает несколько секунд. Посетитель в этот момент может получить смесь старых и новых файлов: сломанную страницу или ошибку 500. Если не выполнить `composer install`, а новому коду нужны новые библиотеки, то их в `vendor/` не будет, и сайт упадёт с ошибкой (например, «класс не найден» или `vendor/ is missing`).

### Контрольные вопросы

### 1. Как проходит запрос от браузера до базы данных?

Браузер отправляет запрос на сервер. Nginx принимает его и передаёт PHP-запросы в PHP-FPM. PHP выполняет код приложения и при необходимости обращается к PostgreSQL. После обработки результат возвращается пользователю в браузер.

### 2. Почему сервер может скачивать код из репозитория, но не может отправлять изменения?

Репозиторий публичный, поэтому сервер может получать код без авторизации. Для отправки изменений необходимы права доступа и аутентификация. Это повышает безопасность: даже при взломе сервера злоумышленник не получает автоматическую возможность изменять исходный код в GitHub.

### 3. Что произойдёт с файлами при удалении экземпляра EC2?

Если файлы и база данных находятся на корневом диске EBS, который удаляется вместе с экземпляром, данные могут быть потеряны. Чтобы избежать этого, необходимо создавать резервные копии или хранить важные данные отдельно от виртуального сервера.

### 4. Что общего у ручного развёртывания и CI/CD?

В обоих случаях код загружается из репозитория, устанавливаются зависимости и обновляется приложение. Разница заключается в том, что при ручном развёртывании команды выполняет человек, а CI/CD автоматизирует этот процесс, включая тестирование и проверку результата.
